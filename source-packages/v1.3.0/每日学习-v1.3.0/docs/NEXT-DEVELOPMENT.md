**App 内更新的使用过程**

1. 电脑完成修改、测试、构建，用现有个人签名生成正式 APK。
2. 发布 APK、版本清单和更新说明到手机可访问的 HTTPS 地址。
3. App 在用户点击「检查更新」时获取清单；后续可加入启动后低频检查。普通页面不常驻解释下载或发布原理。
4. 发现新版本后显示版本号、更新内容和下载按钮，用户在手机内下载。
5. 校验完整性、包名、版本号并比对签名证书；处理活动计时及未保存输入，再打开 Android 安装界面。
6. 系统需要授权或确认时，由用户完成。安装后重新读取实际安装版本；不把发起安装当成完成。

首次需要安装一个带更新入口的版本。以后 APK 仍需要通过网络下载，但无需手动找文件或从电脑传送。此方案是 App 主动检查发布地址；不声称后台服务器通知推送或无条件静默安装已实现。

**发布地址与本机条件**

本机已安装 Android SDK、JDK 和 GitHub CLI，GitHub 当前登录 gaspainting。当前工作目录没有 Git 元数据，也没有连接实体手机。现有 APK 签名文件可继续用于覆盖升级；私钥始终留在本机。

用户已选择专用公开仓库，只上传 APK、update.json 和更新说明；[gaspainting/daily-study-releases](https://github.com/gaspainting/daily-study-releases) 已创建为公开仓库。公开 APK 可由其他人下载并查看默认计划；源码和签名私钥不上传，不能把个人 GitHub 长期令牌打包到 APK。

v1.3.0 已发布为正式 latest；三个资源的 API 摘要、实际下载内容及稳定清单均已核对。模拟器已通过真实联网下载和系统覆盖安装验证，详见 [v1.3.0 报告](V1.3.0.md)。GitHub 在 vivo 手机当前网络中的连通性尚未测试。操作约定见 [App 内更新与发行通道](APP-UPDATES.md)。

**版本清单约定**

清单至少包含 formatVersion、packageName、versionCode、versionName、minSdk、apkUrl、apkBytes、apkSha256、signerSha256 和 releaseNotes。比较升级使用 versionCode，不把显示版本字符串当数值比较；清单读取和 APK 下载均使用 HTTPS。更新来源可更换，但必须显式配置可信地址。

下载后重新读取 APK 元数据和签名，与清单及已安装应用核对。摘要只能检测内容变化，不能代替安装包签名。允许网络失败、取消、未授权安装以及下载损坏时重试；失败保留当前安装和记录，不通过卸载来解决签名不一致。

当前采用用户确认的安装流程。Android 对请求安装的权限、待用户确认回调和无交互更新有具体条件，vivo 行为须实测，不先承诺零点击更新。只在主动开始安装时处理相关权限，不在正常启动时弹出授权。

**数据兼容与实施依赖**

Java DataStore 与 JS model 当前均为严格 schema 1 校验。新增归档、按科目复盘、多计划字段须同步迁移和验证；旧 JSON、完整 ZIP、恢复日志及取消保护随变更一起交付。草稿与下载状态独立保存，不将草稿或下载进度写入正式学习记录。

安装更新会影响运行中的进程，实际安装前必须处理计时和输入；后台下载不能擅自结束计时或把未保存输入称为已保存。

下一阶段验证包括：新旧数据迁移、草稿冲突、归档后的历史统计、报表空值语义；更新清单旧版本/新版本/格式错误、HTTPS重定向与下载失败、损坏/错包名/错签名/回退APK、安装权限拒绝及返回、取消、活动计时保护、覆盖后版本与数据。vivo X100s / Android16 真机验证单独记录。

**依据**

- [Android ADB](https://developer.android.com/tools/adb)：无线配对和直接安装可用于开发调试，但用户本次选择 App 内更新。
- [PackageInstaller 安装交互](https://developer.android.com/reference/android/content/pm/PackageInstaller.SessionParams#setRequireUserAction(int))：处理真实用户确认结果，不能发起安装就称成功。
- [GitHub Release 资源](https://docs.github.com/en/rest/releases/assets)及[稳定下载链接](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)：可作为 APK 与版本清单的发布载体。
