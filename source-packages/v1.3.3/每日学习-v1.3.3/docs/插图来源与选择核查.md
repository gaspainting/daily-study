# 插图来源与选择核查

核查日期：2026年10月13日。依据用户最新要求：**不采用离线插画方案，尽可能联网获取正常图片。**

## 异常图的原因与处理

开发预览里出现过密集黑点的图片，来自早期本地程序插画，原因是绘图透明度被后续颜色设置覆盖，纹理点又继承了过大的线宽。该实现未经过足够的实际图片检查，效果不符合要求。

现在取消这一图片来源：正式APP不包含OriginalArt类，不生成本地插画，也不将程序示意图当作日签图片。浏览器预览同样移除替代SVG插画。主界面的导航图标仍是正常的单色界面图标。

## 当前图片来源

| 来源 | 获取方式 | 核对的信息 |
|---|---|---|
| [Lorem Picsum](https://picsum.photos/) | 从官方图片列表选择ID，再按ID下载1000×750照片 | 图片ID、原图尺寸、作者、Unsplash原页面；图片取得后固定缓存。 |
| [Met开放藏品API](https://metmuseum.github.io/) | 查询具体作品的实时记录，下载primaryImageSmall | 每次检查isPublicDomain=true、图片URL、艺术家、作品名与作品页面。 |

Picsum说明图片来自Unsplash；保存作者和原始页面。[Unsplash许可](https://unsplash.com/license)支持免费使用这些图片，禁止原样销售图片或复制竞争图库服务。本APP将照片用于个人图文卡并保留署名。

Met的[开放访问说明](https://www.metmuseum.org/hubs/open-access)对开放的公共领域作品图片采用CC0。不能仅因作品年代较早或过去文档示例曾提供图片，就推定当前API仍可使用；实时记录没有公共领域标记或没有图片时直接跳过。

图片可以与文字独立搭配；来源稳定性和风格覆盖不等于所有图文都语义配套。不会为了制造“每天不同”而对同一图片随机撒点、改色或生成替代画面。

## 图片进入素材池的条件

1. 请求仅使用支持来源的HTTPS域名，重定向也重新检查域名；失败页面和不支持地址不进入图片池。
2. 下载体积不超过8MB，有Content-Length时核对是否完整取得。
3. 实际文件必须是JPEG或PNG；检查文件签名和结尾标识，拒绝明显截断文件。
4. 最短边至少240像素，最长边不超过10000像素，总像素不超过2400万；进行实际解码，不能只看URL后缀或尺寸头。
5. 保存图片来源ID和SHA256。使用历史同时检查来源ID与文件摘要，避免换网址或重新配文字就绕过去重。
6. 保留作者、作品名、来源页面与素材使用说明，图文详情和导出可查看来源。

这些检查保证图片来源和文件结构可核对。它们不会把抽象作品、黑白照片、低落主题或特殊色彩自动视为异常；用户允许各种风格和主题。

## 选择优先级与网络失败

★ 有未展示的完整联网图文时优先使用。没有新图片时先尝试联网补充；仍未取得时，如果此前已经成功下载过图片，可以选择较久未展示的缓存图片，并记录图片复用状态。

本地缓存保存的是之前实际联网取得的同一张图片，用于历史、收藏、备份和断网回看。缓存与内置离线插画不是同一方案：安装包没有预装日签图片。

首次使用若尚无图片，开屏提供获取状态和跳过按钮，等待最多8秒后进入学习页面；取得图文后正常展示5秒。抽签只有在完整图文就绪并原子保存后才算成功。完全无图片时提示重试，不消耗资格、不生成替代图、不影响学习打卡。

文字继续优先联网获取中文语句；外文只选已有中文释义的内容。保留原创双语文字作为语句补充，搭配的图片仍必须来自真实联网来源。
