本方案为每日学习建立自动评估机制，确定随 v1.6.7 优先交付。每天根据事先确定的计划、已保存记录和固定规则生成结果，取消“照常、减量、仅回顾、休息”的每日评估选择器。普通学习、计划回顾和计划休息分别处理；目标完成、数据完整性和实际活动类型分别呈现。

评估对象是“已记录的计划执行情况”。时间、词数和勾选可以说明记录了多少投入或执行，不能单独证明知识掌握，也不能验证所有手工输入是否真实。方案的客观性来自统一规则、固定依据和可追溯修改。

项目基线为[每日学习项目功能与开发进度总览 v1.6.6](V1.6.6.md)，重点对应第 4 至 6 节。版本安排衔接[后续开发阶段表和视觉重做方案](DEVELOPMENT-ROADMAP.md)。以下阈值与统计口径为拟采用的产品规则，发布日期以验收结果为准。

# 需要同时修改的四处规则

现行机制不仅依赖当日模式，还允许修改目标后重评，并以已评级日期作为完成率分母。因此，移除选择器时需要同时改动以下规则。

| 位置 | 新规则 |
| - | - |
| 当日模式 | 每天直接记录，系统自动评估；低投入不触发目标减半 |
| 评估依据 | 使用当天开始前已确定的目标与日程；事后调整保留原依据 |
| 数据缺失 | 空白、显式 0、部分记录、单位错误、草稿分别处理 |
| 周月统计 | 主指标覆盖全部已结束的计划学习日；缺失日保留在分母并单列 |

“减量”退出评估模式。未来需要降低负荷时，在计划中提前设置较低的真实目标；当天完成较少，只改变完成结果，不反过来降低当天标准。

# 自动评估的组成

| 信息 | 来源 | 示例 |
| - | - | - |
| 计划日类型 | 当日固定日程和必达目标 | 普通学习日、计划回顾日、计划休息日 |
| 记录状态 | 正式保存数据 | 未记录、待补全、记录完整、需核对 |
| 目标结果 | 每项实际值与固定目标比较 | 部分完成、基础达标、标准达标、充分达标、时长超额 |
| 活动类型 | 有明确来源的实际记录 | 已记录回顾、仅回顾、回顾与其他学习、类型未明确 |

计划回顾日属于事先安排；实际仅回顾属于事后事实。普通学习日仅记录了回顾，也要继续核对原定的新学与其他必达目标。计划休息属于日历安排，不能从没有记录、时长很少或目标为 0 推断。

界面主摘要使用“全部必达目标已完成”“部分目标完成”“待补全”等准确结果。时间等级放在时间维度，避免用“时长充分达标”替代整天的目标结论。

# 日程与评估依据

## 日类型的自动确定

日程来源按“指定日期安排、每周重复安排、计划默认安排”的优先级解析，且只能使用当天开始前已确定的版本。现有周日学习安排保持原配置；周末、节假日或没有课都不自动等于休息。

| 固定安排 | 自动日类型 | 处理 |
| - | - | - |
| 显式安排休息，且没有必达学习目标 | 计划休息日 | 不参加学习达标率；允许记录自主学习 |
| 有非空必达目标，且全部属于回顾 | 计划回顾日 | 逐项核对回顾目标 |
| 必达集合非空，且不全属于回顾 | 普通学习日 | 按该日必达目标核对 |
| 没有必达目标，也没有休息安排 | 未安排必达目标 | 可记录实际及参考目标；不生成自动达标 |
| 同时安排休息和必达学习任务 | 安排冲突 | 计划保存前提示解决；遗留冲突列为待核对，不能当成已验证的休息日排除 |

用户可以在计划中一次安排每周重复规则，或提前安排特殊日期。日常记录页面无需再次选择评估模式。仅回顾日也可以由“当天只安排回顾类必达目标”直接推导。

日程或目标解析失败时保留已知的原计划身份，并将当天标为待核对；不能把配置错误当成无计划来缩小分母。

现有“休息时段”控制计时和提醒的允许时间，与“休息日”独立。到达 20:30 等计时边界不会把学习日改成休息日。

## 固定依据的时间

以计划时区的当日 00:00 为默认日期边界。评估依据包括目标、单位、必达范围、活动角色、日程来源和算法版本。App 即使午夜未运行，也应根据保留的计划修订记录取回当时已确定的版本；不能等到首次打开或首次保存才允许决定当天标准。

普通计划修改默认从下一天或用户选择的未来日期生效。当日执行安排可调整，但主统计继续使用原计划依据；调整后结果作为带说明的对照。新建计划的当天可以记录和显示创建后的目标，标记为首日部分时段，主整日统计从下一天开始，不补造创建前的要求。

跨时区、日期纠正和计划日期变化保留原记录的日期及依据。已经结束的日期不因缩短计划范围、归档科目或移动任务而从历史计划统计中消失。

# 记录状态与当天进度

先检查数据是否足够，再给出目标结论。以下“必需字段”只指计算当天必达目标所需的输入；随记、备注和不参与评估的额外记录不要求每天填全。

| 输入情况 | 显示 | 评价与统计 |
| - | - | - |
| 没有相关正式记录 | 未记录 | 不推断为 0；已结束的计划日仍进入主分母 |
| 部分必需字段有值，其他为空 | 待补全 | 已知维度可以显示结果；不宣称全部完成 |
| 必需字段明确为 0 | 对应目标未完成 | 0 是已记录事实；不能自动改为休息 |
| 正式数据完整且单位一致 | 按各目标计算 | 可给出完整的当日目标结论 |
| 单位不符或目标依据无效 | 需核对 | 不视为达标，不借此移除计划日期 |
| 草稿已改、尚未保存 | 待保存 | 正式评估仍使用上一次成功保存的数据 |
| 当前日期尚未结束 | 进行中 | 显示当前结果或距目标的差额，不提前算作一个完整失败日 |

时长为空但词数已有记录时，显示“时长未记录”和整体“待补全”，不能说整天没有记录。所有必达字段为 0 时也只说明这些目标没有记录到投入；若存在额外学习，仍单独展示。

可以提供可选操作“将其余未填的必达项记为 0”，先列出涉及字段，由用户确认并正常保存；保存动作本身不能自动补零。日期结束不会禁止补记。补记成功后按原依据重新计算，显示补记或修订时间。

# 普通学习日的计算规则

## 时间区间

设固定时间参考为 [L,U]，T 为该范围内正式保存的实际时长。下限 L 表示最低计划要求，上限 U 表示参考投入上沿，二者不能在看到 T 之后自动变化。

当 0 < L < U 时，区间内部采用三等分作为初始展示规则：

- B1 = L + (U − L) / 3

- B2 = L + 2 × (U − L) / 3

| 条件 | 时间结果 | 是否达到最低时间目标 |
| - | - | - |
| 必需时间字段为空或未补全 | 未记录或待补全 | 尚不能确认 |
| 字段完整且 T = 0 | 未投入 | 否 |
| 0 < T < L | 部分完成 | 否 |
| L ≤ T < B1 | 基础达标 | 是 |
| B1 ≤ T < B2 | 标准达标 | 是 |
| B2 ≤ T ≤ U | 充分达标 | 是 |
| T > U | 时长超额 | 是，但不增加达标天数 |

三等分是可解释的产品默认值，不是经验证的学习质量分界。“基础达标”明确表示已经达到下限，避免与旧“减量后按半目标评估”混淆。超过上限只说明时间超过参考，不代表效果更好，也不要求用户继续计时来提高总分。

参考 60—120 分钟时：40 分钟为部分完成；60 与 79 分钟为基础达标；80、90 与 99 分钟为标准达标；100 与 120 分钟为充分达标；121 分钟为时长超额。刚好达到下限算达标，刚好达到上限仍属于区间内。

## 特殊目标

固定目标 L = U > 0 时，只比较未达到、达到、超过，不强行划出三个区间。L = 0 时没有正的最低投入要求，该维度只能用于记录或参考上沿，不能独自产生一个达标日。L = U = 0 不等于休息；L < 0、U < L 或非法值属于依据错误。

实现采用一致的整数精度。内部可以用秒以及交叉相乘比较三等分边界，展示按分钟格式化；不先四舍五入实际值再决定等级。未来阈值调整使用新规则版本，不改写过去的分级。

## 词数与其他数量

单词新学、单词复习和各类数量分别比较，不把分钟、词、题、页或组折算为一个总量。正的固定数量目标 Q 采用：空值为未记录，0 为未投入，0 < q < Q 为部分完成，q = Q 为达标，q > Q 为数量超额。整数目标保留整数，例如 3 题完成 2 题仍为部分完成。

目标单位和实际单位必须一致。新学与复习词数不互相抵扣；复习数量只有事先设置了目标才参与该维度评价。未设目标的数量照常统计，不制造完成比例。

## 全天目标结论

计划中事先标明每项指标是“必达”还是“参考”。全天达标要求：必达集合非空、所有必要输入完整有效、每个必达目标都满足最低要求。高于参考的某一项不能抵消另一项必达目标的不足。

为保持迁移清楚，既有总时长可继续作为一个必达目标；时间分项默认保留参考用途，不从原来的分配表暗中新增逐科硬要求。若要落实课程优先，建议明确将课程复习最低量设为必达，自约定的未来日期开始。其他时间可以在已约定的目标组内调剂。

需要区分“总时长达标”与“全部目标达标”。例如总时间 110 分钟已经达标，新学目标 40 词只记录 20 词，则整体仍是部分目标完成。反之，未来若任务结果已完成而用时较短，可以分别显示任务完成与时长未达；若时间只作参考，应在未来计划里提前改变其角色。

# 计划回顾日与实际仅回顾

## 计划回顾日的标准

计划回顾日以提前设置的回顾目标为依据，可以包括课程回顾时间 [Lr,Ur]、单词复习数量 Wr，以及后续版本支持的指定回顾事项。只核对事先确定的必达回顾维度；新学目标默认不属于计划回顾日的必达集合。

回顾时间使用与普通时间相同的区间等级，目标值来自当天独立的回顾安排，不从当天做了多少倒推。数量按自己的单位比较；条目执行与用时独立。

例如提前安排回顾 45—60 分钟、复习 80 词，两项均必达。实际为 50 分钟、80 词，记录完整，则为“回顾日达标”；实际为 20 分钟、80 词，则为“复习词数达标，回顾时间部分完成”；实际时间为空，则为待补全。

回顾日额外新学 5 词，应保存并显示“回顾与新学”，不会取消已经满足的回顾日目标。日程名称表示原计划用途，并不禁止真实的额外学习。

## 普通学习日实际仅回顾

若普通日原定总时间 60—120 分钟、新学 40 词，实际只回顾 35 分钟、新学明确为 0，则显示“仅回顾”“时间部分完成”“新学未完成”，不能自动切换到回顾日标准。

自动识别使用结构化来源：课程复习、单词复习、明确属于回顾的科目或任务。科目名称含“复习”、笔记写了“回顾”、时间很短或新学没有填写，都不足以自动确认仅回顾。

判定“仅回顾”需要至少一个正的回顾记录或有效回顾事件，没有正的新学或其他学习记录，没有影响结论的未知类型，也没有尚未填写、可能包含其他学习的必需输入。条件不足时显示“已记录回顾”或“活动类型待补全”。该标签仅描述 App 记录范围。

活动角色从明确的科目、任务或记录来源继承，并保存当时角色；一般时间与题数无法分类时保留未知。无需每天再选择一次整体活动模式。更改科目名称或未来角色不改变过去记录的解释。

## 回顾队列的后续扩展

v1.6.7 使用已有课程回顾时间和单词复习数量实现完整的回顾日评估。v2.3.0 再接入回顾队列：按当天开始时确定的应回顾条目集合计数，按条目 ID 去重；同一条目反复点击不重复完成目标，删除、延期、暂停不自动变成已完成。

没有到期条目时，条目维度显示“无到期回顾”，不计算 0 ÷ 0 或 100%；其他已设回顾目标仍独立核对。新加入条目默认是额外回顾或未来安排，不能无痕改变原集合。

记录“想起了、需要提示、未想起”等回顾反馈，有助于区分执行与回忆表现；反馈或自评分不能直接包装成客观掌握率。若以后接入实际小测，再按明确题目和评分规则展示结果。IES 的[学习与教学组织实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)提出使用提取测验与延后学习判断；它不为本方案的时长三等分阈值提供验证。

# 休息日的独立规则

| 场景 | 自动结果 | 学习达标率处理 |
| - | - | - |
| 提前确定休息，没有学习记录 | 计划休息；实际未记录 | 不进入学习日分母，也不获得一个达标日 |
| 提前确定休息，明确记录为 0 | 计划休息；已记录 0 | 同上 |
| 提前确定休息，有学习记录 | 计划休息；自主学习及实际数量 | 学习量可以汇总，不补算学习达标日 |
| 普通学习日没有记录 | 未记录 | 日期结束后进入主分母，单列缺口 |
| 普通学习日必达项明确为 0 | 对应目标未完成 | 保留原计划评价 |
| 当天临时决定休息或中断 | 临时中断备注及原目标结果 | 不自动变为预定休息，不移除主分母 |
| 全部目标为 0，但没有休息规则 | 未安排目标 | 不自动达标，也不当作休息 |

系统能确认的是“这天事先安排休息”，不能仅凭没有学习记录证明用户实际休息了多久或恢复得怎样。因此不设“休息质量分”，也不把休息标成失败。

生病、突发事务或临时任务可以记录原因并调整后续安排，不要求上传证明。原因用于解释计划偏差，不产生新的免责按钮。需要查看调整后口径时可以单独展示，并同时保留原计划结果和异常天数；首版主卡片只显示一套明确的原计划统计。

# 防止评价依据随结果漂移

| 后续操作 | 处理原则 |
| - | - |
| 晚上降低当天目标 | 保存调整，主评价仍按原目标；可以查看调整后对照 |
| 当天改为休息 | 保留原计划日类型，记临时调整；未来日期可正常改变 |
| 把未完成任务移到明天 | 原安排保留未完成或延期，新日期形成新安排，不能改写原执行结果 |
| 清空不利的实际记录 | 改为未记录或待补全，原计划日期仍在分母 |
| 补记真实学习 | 正常接受，按原目标重新计算，保留补记时间 |
| 修正实际输入错误 | 保留变更前后值和修订时间，按修正事实计算 |
| 修正原目标录入错误 | 提供明确的更正记录与前后对照，不静默替换原计划趋势 |
| 归档科目或缩短计划日期 | 历史义务与快照保留，不因此删除过去的分母 |

自动分级减少通过切换模式改变结论的空间，但本地自报工具不能阻止所有虚假填数、改系统日期或修改备份。无需为此引入摄像头监督、强制联网或复杂证明。第一版保证 App 自己的规则一致、修改有迹可循，并清楚保留输入来源。

计时继续复用原生能力。Android [SystemClock 文档](https://developer.android.com/reference/android/os/SystemClock)区分可被调整的日历时钟与适合测量经过时间的 elapsedRealtime。实现应检查净计时是否使用单调时间，并独立保存日期归属；重启、改时区、跨日和时间跳变都不能回滚已固定的评估依据。

# 周月统计的新口径

统计按计划分别进行，只包括自动评估生效后的范围。主整日指标统计截至昨天已经结束的日期；今天显示进行中，未来日期不进入分母。

- D：原计划中已经结束的普通学习日和计划回顾日数量。未记录、待补全、临时中断和需核对的这些日期仍保留；仅预先有效的休息日不计入。

- C：D 中所有必达输入完整、有效且可以评价的日期数。明确填写 0 也属于完整记录。

- P：C 中所有必达目标达到最低要求的日期数。

| 指标 | 公式 | 作用 |
| - | - | - |
| 计划达标率 | P ÷ D | 主指标，衡量有记录支持的计划完成情况 |
| 记录完整率 | C ÷ D | 显示主指标覆盖了多少完整记录 |
| 已完整记录日达标率 | P ÷ C | 次要分析，必须与覆盖范围一起显示 |

例如一周提前安排 6 个学习或回顾日和 1 个休息日。6 个计划日中，4 天记录完整，其中 3 天达标，另外 2 天未记录。计划达标率为 3/6 = 50%；记录完整率为 4/6 ≈ 66.7%；已完整记录日达标率为 3/4 = 75%。主页面不能只展示 75%。

未记录保留为未知事实，并不被断言为没有学习；主指标统计的是“已经确认的达标”。这使缺失不会自动提高百分比。补记可以让确认结果变得更完整。

D = 0 时显示“本期无到期学习安排”；C = 0 时不显示 P/C 的百分比。原计划类型已知但目标缺失的日期保留在 D 并标为待核对；完全缺失原安排来源的日期单列“依据缺失”，不把它们伪装成休息，也不宣称该范围覆盖完整。

普通学习日与回顾日提供分项达标率，避免不同要求混在一个总百分比中难以解释。计划休息、临时中断、未记录、待补全、依据错误分别给出数量。长期低目标也可能使达标率高，因此同时保留绝对学习量和目标变化趋势；系统不因为短期未达标自动降低目标。

# 界面与文案

今日页面保留目标、实际、自动结果和查看依据。删除每日评估模式选择器，并在保存成功后更新正式结果；草稿预览始终标明尚未保存。

示例一：普通学习日的卡片可显示“部分目标完成”，下方列出“时间 90 / 60—120 分钟 · 标准达标”“新学 20 / 40 词 · 部分完成”“记录完整”。操作只保留“继续记录”和“查看依据”。

示例二：计划回顾日显示“回顾日达标”，下方列出回顾时间和复习词数；示例三：计划休息日有学习时显示“计划休息 · 已记录学习 20 分钟”。无记录时只显示“计划休息”，展开详情可查看记录状态。

“查看依据”展示当时目标、来源、生效日期、实际值及简短判定理由，例如“90 分钟位于 80—100 分钟区间”。算法版本、修订详情等放在详情或导出中，不占据高频操作页面。

状态使用文字与图形共同表达，颜色用于辅助识别。延续整体视觉规范的大字号、浅深色和无障碍要求。避免“不合格的人”“你今天不够努力”等人格判断，也不加入自我辩护、重复安慰或内部实现说明。

# 技术结构与迁移

## 数据职责

| 对象 | 主要内容 | 约束 |
| - | - | - |
| 计划修订 | 生效日期、保存时间、时区、日程、目标与必达范围 | 能还原当天开始前已经确定的计划 |
| 每日评估依据 | planId、日期、来源修订、冻结边界、规则版本、目标与单位快照 | 复用并扩展现有评估依据，后续编辑不原地覆盖 |
| 正式实际记录 | 时长、数量、来源、活动角色、修订 | 保留手动保存、空值与 0，草稿独立 |
| 调整与更正 | 原值、新值、记录时间、影响日期、原因 | 实际修正与计划调整分开 |
| 派生评估 | 记录状态、分项结果、整体结果、活动类型、理由代码 | 可重算，缓存键包含依据版本和实际修订 |

评估入口可定义为 evaluateDay(basis, savedRecord, recordRevision, dayPhase)，纯函数返回结果和判定依据。当前时间由调用方解析为日期阶段后传入，函数本身不读取系统时钟，不直接写存储。

Java 与 JavaScript 使用同一组边界输入和预期输出核对；正式保存结果由原生提交成功后发布。今日、历史、复盘、小组件、CSV 和 PDF 共用同一口径。新字段同步进入草稿、备份、恢复与严格校验；近期无需以数据库迁移为前提。

正式日总数是实际值的唯一计数入口，已汇入总数的计时明细不能再次叠加；若来源明细参与计算，要按会话和记录标识去重。已知重叠计时应核对，同一段时间不能同时成为两个科目的独立净学习量。手工总数与明细矛盾时提示修正，不静默猜测。

## 历史兼容

v1.6.7 首次迁移成功时保存已有目标、有效依据和日程来源，立即启用自动分项展示并取消每日模式选择。升级当天作为过渡日，保留已有旧结果，新输入仍可正常保存；新的完整日统计默认从计划时区次日 00:00 开始，不把升级前的安排伪装成提前冻结的新规则依据。生效日前保留旧的照常、减量、仅回顾和休息字段、原评估依据及结果，显示为旧规则历史；重新保存不能自动改写为新规则。

未来默认安排沿用已知参考值；只有来源与时间明确的提前安排才可成为新的休息或回顾日程，其他情况在计划设置中明确为未来安排。旧记录缺少活动分类时保留未知，不通过名称猜造。

如提供旧历史的新规则对照，只生成单独的比较结果，不替换正式历史。报表明确区分生效前后口径，不将两种完成率直接拼接成同一条无标记趋势。schema 版本由实施时当前基线分配，并覆盖旧格式导入、新格式备份往返及失败回滚。

# 关键验收样例

以下是实施时必须验证的设计用例，不代表已运行 App 测试。

| 场景 | 预期结果 |
| - | - |
| 普通日全空 | 未记录；日期结束后保留在计划分母 |
| 一项填 0，另一必需项空白 | 待补全；不能断定全天未学习 |
| 时间目标 60—120，实际 0、59、60、80、100、120、121 | 未投入、部分、基础、标准、充分、充分、超额 |
| 时间目标固定为 60，实际 60 | 达标；没有除以零或伪造区间 |
| 目标 0—0，有实际 20 分钟 | 额外投入；不自动休息或产生 100% |
| 目标 3 题，实际 3 页 | 单位不符，不能达标 |
| 总时长达标，另一必达科目或词数不足 | 部分目标完成，不能被超额时间抵消 |
| 只记录回顾，但新学仍为空 | 已记录回顾、待补全；不能确认仅回顾 |
| 原普通日只回顾 35 分钟，新学 0 | 按原标准部分完成或未完成，不自动换日型 |
| 计划回顾日所有必达回顾量完成，另新学 5 词 | 回顾日达标，额外新学保留 |
| 计划休息日学习 20 分钟 | 计划休息加实际学习量，不增加达标日 |
| 当天未完成后降低目标或改休息 | 原计划结果和分母保留，调整有记录 |
| 删除、延期或反复勾选同一回顾项 | 不自动完成，不重复计数 |
| 正式值 40，草稿 90 未保存 | 正式评估仍按 40，另示待保存 |
| 补记历史真实学习 | 按历史基准重算并保留补记时间 |
| 调整未来目标、单位、日程或计划范围 | 不改写已结束日期的事实、依据和分母 |
| 一周 D=6、C=4、P=3 | 主达标率 50%，完整率 66.7%，条件达标率 75% |
| 修改旧版减量或休息记录 | 保留原规则，不能默认套成新版普通日 |
| 无到期学习日或无回顾条目 | 显示无安排，不出现 0/0 或自动 100% |
| 跨日、改时区、重启和设备时间跳变 | 计时与日期分别处理，历史依据不回滚 |
