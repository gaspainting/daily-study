# v1.6.2 界面与交互

目标是让新增功能有明确位置，缩短查找和记录路径。保留清楚的文字、单位和输入状态，重新建立页面层级。

**参考比较**

| 参考 | 本轮观察与采用 | 在本 App 中的取舍 |
|---|---|---|
| [Apple 官网](https://www.apple.com/) | 清楚的主导航、分区和主次按钮 | 采用层级与动作区分，录入页保持紧凑 |
| [OpenAI 官网](https://openai.com/zh-Hans-CN/) | 中心任务区域和直接可见的快捷入口 | 将今日任务入口集中在概览下面 |
| [Claude 官网](https://claude.com/) | 克制的中性色、边界和清楚的主要动作 | 采用浅底、白色模块与深绿强调，正文使用系统中文字体 |
| [IBM Carbon 标签页规范](https://www.carbondesignsystem.com/building-blocks/core/components/tabs/guidelines) | 同一页面内切换相关工作区 | 今日、计划、复盘和设置分组，输入控件留在原表单 |
| [TickTick](https://help.ticktick.com/) 与 [Todoist](https://www.todoist.com/help/todoist/features/use-the-board-layout-in-todoist-AiAVsyEI) | 按任务组织、减少同屏竞争 | 每次聚焦一个模块和科目，顶部摘要保留整体状态 |
| [Linear](https://linear.app/features) | 功能分组与概览 | 用于比较信息组织；本轮只阅读页面内容 |
| [WAI-ARIA 标签页模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) | 标签与面板关联、焦点、方向键与选中状态 | 实现 tablist/tab/tabpanel、方向键和 Home/End |

Apple、OpenAI、Claude 首页已通过浏览器截图查看；Carbon、WAI-ARIA 和上述产品帮助页用于阅读交互规范。搜索范围还包括 Google 和 NVIDIA；未将未成功打开的 NVIDIA 页面作为视觉验证依据。比较后选择适合每日录入的结构，未引入远程字体、UI 框架或品牌素材。

**页面结构**

| 页面 | 一级模块 | 主要操作 |
|---|---|---|
| 今日 | 记录 / 课程 / 周目标 / 评估 | 记录区切换科目，底部保存当天；其他模块有各自入口 |
| 计划 | 日程 / 科目 / 计划设置 | 科目编辑按科展开；日期、课表区间与周末安排集中管理 |
| 周复盘 | 总览 / 科目统计 / 本周随记 | 总览查看进度，统计查看各科，随记单独填写 |
| 设置 | 提醒 / 备份与报表 / 应用 | 使用手册始终可见，应用组包含小组件、休息时段和关于 |

今日安排放在记录区末尾，可展开编辑。已选择的安排显示在折叠标题旁。科目按钮直接显示当前输入摘要，空白与 0 分别呈现。大字号或超过 6 个科目时，使用带名称的科目选择框。模块切换保留输入，保存失败时仍有重试；表单校验会打开发生错误的科目。

主要按钮、表单边界、焦点和选中状态均有明确视觉标识。底栏与保存区使用实色背景。标签页在窄屏和大字号下可横向滚动，方向键切换会将当前标签带入视野。

界面通过独立的 DOM 分组层与样式完成，现有记录、计时、草稿与保存处理继续使用原有模块。实际验证结果见 [V1.6.2](V1.6.2.md)。
