# v1.6.4 · 白底列表界面

用户在两套可操作样稿中选择 A。正式界面沿用 A 的白底、黑色标题、蓝色主操作、细分隔线和连续列表。

**视觉参考**

- [Things 官方页面](https://culturedcode.com/things/)：字体层级、连续列表、克制的功能色。
- [Apple 提醒事项](https://support.apple.com/en-us/102484)：白底、字段分组、集中编辑和清楚的主要动作。
- 比较过 [Linear Mobile](https://linear.app/mobile) 的深色工作台方案。用户选择白底列表，因此正式界面采用 A。

参考为具体页面的构图和层级观察。项目使用系统字体与已有 SVG 图标方式，不引入品牌图像、专有字体或新 UI 框架。

**界面变化**

| 页面 | 实现 |
| --- | --- |
| 今日 | 左侧实际时长、右侧可点的总参考区间；记录、课程、本周、评估采用细线标签；科目同时显示为列表 |
| 科目编辑 | 点列表行打开集中编辑；分钟、单词新学/复习、数量及单位沿用原字段；“完成”关闭编辑，底部“保存记录”提交 |
| 今日安排与随记 | 各有明确入口，打开各自的编辑内容；原存储枚举及休息记录保留 |
| 计划 | 本周安排、科目、计划设置；周列表突出当天总参考与课程摘要，记录状态独立显示 |
| 复盘 | 周、月、历史与计时明细保留；模块、图表、随记统一字体与分隔线 |
| 设置 | 学习、数据、应用三组连续列表；提醒、休息时段、备份、小组件、手册与关于直接可见 |
| 日签 | 联网图片、文字、释义与署名沿用真实数据；统一公共导航、操作色及排版 |

**字段与保存**

科目编辑器是原记录表单内的原生 `dialog`。原有控件保留 ID、name、表单归属和草稿键，全部科目共同提交一次。单词分次明细、单位快照、旧单词时长和统计来源不改写。

输入时列表预览跟随表单；有未保存修改时显示“待保存”，时长标为“填写时长”。正式评估继续读取已保存记录。空白、0、无效输入和部分记录分别显示。表单验证会打开含错误字段的编辑器。

系统返回先关闭当前弹层。后台返回和目标修改引发重绘时恢复当前编辑位置；跨日期、跨计划不沿用旧编辑器。主编辑、参考目标与单词明细弹层按实际打开层级关闭。保存失败继续提供原表单重试。

计时入口调用既有原生计时，不为数量或单词增加计时。进入休息时段的限制、原生权限申请、备份校验与覆盖确认、更新下载安装均沿用原实现。

**代码范围**

- `layout.js`：列表、模块分组、集中编辑、返回与编辑位置恢复。
- `layout.css`：白底样式、主操作色、列表及大字号布局。
- `app.js` / `index.html`：紧凑计划页头、实际与参考顺序、计时科目入口、编辑器与原页面生命周期衔接。
- 原生窗口背景与系统强调色统一为白底、蓝色操作；版本由 Android 构建元数据提供。
- 手册路径与界面标签同步更新。

数据库与备份 schema 继续为 8，评估规则、参考生成、统计、学习记录与历史迁移算法没有更换。
