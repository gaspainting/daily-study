# v1.4.0 开发与验证

2026年10月18日。versionName 1.4.0 / versionCode 10，基线为7ddd302，修改前工作区干净。沿用Java Activity、APK内HTML/CSS/JS及现有构建流程。

**本轮交付**

| 功能 | 入口及行为 |
|---|---|
| 自填任务清单 | 今日、计划或复盘 → 编辑本周目标；任务可添加、编辑、排序、关联科目、删除和撤销删除 |
| 今日勾选 | 勾选后出现保存操作；成功保存后进入正式任务状态 |
| 周复盘 | 按已完成、未完成分组，保留整体目标与随记；引用正式保存的状态 |
| 历史目标 | 原日期分组可查看、编辑，教学周编号调整不改任务归属 |
| 移动目标 | 选计划内的一周及合并/替换方式，确认日期和覆盖范围后移动 |
| 草稿与冲突 | 按计划、周隔离；重启恢复，冲突按任务ID和字段选择，失败可重试 |
| 备份与报表 | ZIP携带全部计划任务；新版继续读旧ZIP/JSON；PDF收录目标，CSV原列及统计口径不变 |

weekGoals/weekHints文字保留，不拆解为任务。每周最多50项、每项名称最多500字，科目关联可留空。新周任务为空，新计划不复制已完成任务。任务时间记录实际保存操作时间。分钟和词数仍来自原有学习记录。

修改计划开始日期或缩短范围后，目标保留原起始日期，在历史入口显示“原日期分组”。移动先校验完整结果，合并不超过任务和文字上限，取消或失败不提交。相关周有草稿时，先处理草稿再移动。

**改动文件**

- assets/weekly-goals.js：日期归属、稳定ID、字段合并、校验和移动预检；weekly-ui.js：清单、删除撤销和冲突选择。
- app.js、drafts.js、model.js、index.html、polish.css：页面接入、草稿生命周期、schema3、状态及大字号布局。
- DataStore.java、WeeklyGoals.java、DraftStore.java、PlanStore.java：原生校验、旧数据克隆迁移、草稿范围和新计划检查。
- ReportExport.java：PDF目标与清单；schedule.js/CourseSchedule.java：保留schema3，避免编辑操作降级数据标记。
- scripts/package-delivery.py：源码包带上发行JSON/Markdown元数据，可在独立解压后校验源码清单；安装包和签名私钥不收入源码包。
- tests：新增模型、Android原生、WebView和正式APK升级验证；更新既有迁移断言。

**修复与审查**

关闭弹层中的旧表单可能被flush再次写成草稿，覆盖后来输入。现在关闭时移除表单，flush只处理页面和打开的弹层。既有单词及独立表单另行回归。

科目和课程操作原先固定赋schema2，现保留更高的数据版本。任务按ID合并独立修改，删除与修改、同字段并发变更需要选择。详见[相关代码审查](CODE-REVIEW-v1.4.0.md)。
