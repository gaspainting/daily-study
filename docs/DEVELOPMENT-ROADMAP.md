以每日学习 v1.6.6、versionCode 23、schema8 为规划基线，将整体视觉重做、新功能和架构改进纳入同一条开发路线。先确认现有行为与数据边界，再并行完成设计体系和架构接口整理，随后交付完整新界面，再逐步交付自动评估与个人规则、每日任务、回顾与复盘行动。

设计采用 Material Design 作为 Android 组件与平台交互的主要参考，结合 Apple iOS HIG 的内容层级、可读性、直接操作和反馈原则，形成一套统一的 Android 体验。当前 Java 与本地 WebView 可以承接这轮设计；构建系统和数据库分别按维护需求安排。

规划日期为 2026年10月26日。v1.6.6为已知基线，以下新增编号均为开发目标版本；主线明确到v2.4.0，v2.5.0和v2.6.0为候选版本，发布日期按验收结果安排。项目事实依据为[每日学习项目功能与开发进度总览 v1.6.6](V1.6.6.md)。

# 各阶段实施重点

## 阶段0 v1.6.7 使用与数据基线

覆盖五个主页面及编辑、确认、导入、导出、更新和帮助流程，状态包含空白、0、部分记录、待保存、保存中、失败、冲突、休息和单位不一致。

vivo真机重点观察锁屏、省电、后台返回、键盘、实际网络和覆盖升级。复用Android16模拟器自动化，按风险补充最低声明系统和代表性中间系统。TalkBack实际完成输入、保存、关闭弹层与返回。

测量打开到可操作、一次记录的步骤和耗时、保存、长历史查询及导出。观察可持续7至14天，并行进行设计和只读架构梳理。现状明确后再制定性能预算。

## 阶段1 v2.0.0 交互与整体视觉设计

以今日、计划、复盘、日签、设置为信息架构起点，检查高频入口和次级内容的关系。此时完成任务和回顾的接入原型，避免未来把更多内容直接堆到今日页。

至少制作三条可走通的原型：今日输入到正式保存；科目编辑与单词明细调整；总体分配到覆盖范围确认。其余主页面同样提供设计稿和状态说明。

确定主次操作、编辑退出与保存、错误位置、单位和参考值呈现。各页面采用同一套组件规则，避免开发时临时决定颜色、边距和反馈方式。

## 阶段2 v1.7.0 架构边界与规则契约

近期保留Java、HTML、CSS、JavaScript和现有JSON。原生层继续掌握正式提交、计时和平台能力；界面负责输入、草稿、预览和呈现。

为参考、评估、单位、课程、单词明细和迁移建立共用输入输出样例。JS和Java比较规范化业务值，保留两侧必要校验。原生提交结果返回后更新正式状态。 为自动评估分离计划日程、固定目标依据、正式实际与派生结果，加入规则版本和修订接口；本版保持旧规则的对照结果，正式切换安排在v2.1.0。

桥接约定包含请求标识、计划标识、预期修订号、数据内容和结果。处理重复请求、切换计划后的旧回调及超时后的状态核对。只抽取本轮需要的存储接口，不把全面重写设为前置任务。

## 阶段3 v2.0.0 整体视觉实现

v2.0.0-beta.1对应3A，交付主题、公共组件、导航、今日、计划和常用编辑器，用于预览及测试。v2.0.0-beta.2对应3B，补齐复盘、日签、设置、离线手册、导入预览、更新页面与其余状态。两批共同构成完整重做范围，全部验收后发布v2.0.0正式版。

小组件纳入必要调整；分享图和报表检查字体、单位、层级与署名。系统权限、文件选择、分享和安装界面沿用Android流程。

建议本轮交付浅色、深色和跟随系统；动态色作为有回退方案的增强。业务schema优先沿用，主题偏好独立处理。完整视觉切换与数据库迁移分开发布。 自动评估的卡片与状态在本轮设计，行为切换在v2.1.0完成；旧引擎仍依赖模式时保留必要入口。

## 阶段4 v2.1.0 自动评估与个人规则

将提醒安静时段和计时限制分别表达，现有时间表保留为迁移后的默认值。配置明确作用范围和生效日期，先采用最少必要的默认与当天例外层级。 计时与提醒的休息时段和预定休息日分开，时段例外不改变当日评估身份。

取消每日照常、减量、仅回顾和休息的评估选择器。系统按当天开始前已确定的日程、目标及正式记录分项计算；低投入不触发目标减半。计划回顾日核对独立回顾目标，计划休息日不生成学习达标；普通日仅做回顾或临时休息仍保留原目标。空白、0、待补全和单位错误分别处理，旧历史保留原规则。

主统计使用已确认全部达标日数除以已结束的原计划学习与回顾日数，并列记录完整率。未记录、待补全和临时中断不从分母消失，事后调低目标不替换原计划趋势。完整规则、时间阈值、回顾与休息条件、数据模型和验收样例见[每日学习自动评估机制与实施方案](AUTOMATIC-ASSESSMENT-PLAN.md)。

提供启动直接进入今日的选项，以及从小组件、计时通知或快捷入口直达对应操作。输入继续进入草稿并由明确保存动作提交。日签保留独立入口和内容价值。

## 阶段5 v2.2.0 每日任务执行

复用已有周任务身份。第一版支持计划日期、截止日期、可选估时、当天排序、完成、改日期和本次跳过。

区分任务本体与某次日期安排；延期保留原安排和变更，改名或移动保留过去报告所需快照。未完成项进入待处理列表，由用户选择后续安排。

任务勾选、课程清单、计时、词数及数量继续独立。关联用于减少操作，不自动推断完成或补写学习量。新字段同步进入草稿、备份、恢复、必要导出及迁移。

## 阶段6 v2.3.0 问题回顾队列

回顾项保存来源、科目、问题描述与下次日期；回顾事件保存发生时间和反馈。完成一次回顾与结束后续跟进分别处理。 评估使用当天预先确定的应回顾集合并按条目去重，删除、延期或暂停不自动成为已完成。

第一版使用手动日期和少量预设间隔。反馈可表达能独立完成、仍需提示或仍有疑问；不从时长或打卡次数推导精确掌握度。提供暂停和重新安排。

明确原记录删除、科目归档及笔记修改后的来源行为。旧记录不被转换成没有实际发生过的回顾事件。

## 阶段7 v2.4.0 复盘驱动下一周

回答记录是否完整、目标是否合适、哪些任务和问题需要处理，再连接具体动作。

下周目标调整复用总体分配和预览确认；任务迁入复用现有任务流程。建议使用已保存数据，能查看日期、日程类型、规则版本、单位和样本范围；调整由用户确认。 趋势同时显示计划达标率与记录完整率，保留旧规则与新规则的口径边界。

经过2至3个真实周周期，判断哪些入口持续使用、哪些操作重复，再决定模板、阶段目标或自动安排的后续范围。

# 整体视觉重做标准

## 两套规范的采用方式

Material提供可适配的设计系统与组件；HIG提供内容层级、熟悉感、清楚反馈、恢复能力和平台情境方面的参考。项目将其落实为统一的Android组件与行为。参见[Material 3](https://m3.material.io/)和[Apple HIG设计原则](https://developer.apple.com/cn/design/human-interface-guidelines/design-principles)。

| 设计方面 | 本项目采用方式 | 交付内容 |
| - | - | - |
| 平台行为 | Android返回、系统栏、键盘、权限、分享与安装流程 | 返回栈、insets、弹层和焦点规范 |
| 内容层级 | 计划和日期明确；实际、单位、参考、状态顺序稳定 | 页面层级与长内容样例 |
| 颜色 | 背景、表面、正文、次要文字、强调、错误等语义角色 | 设计变量与浅深色映射 |
| 排版 | 有限的标题、正文、标签、辅助文字层级；数字与单位对应 | 字体、行高、换行和缩放规则 |
| 控件 | 统一列表、输入、按钮、筛选、日期选择、弹层和撤销 | 公共组件及按下、焦点、加载、错误等状态 |
| 密度 | 常规记录用列表与分组，独立内容采用合适容器 | 高频界面原型与密度规范 |
| 动效 | 帮助理解切换和状态；减少动态效果时仍可操作 | 动效与低动态方案 |
| 资源 | 适合Android且许可明确的统一字体和图标 | 资源清单、许可和署名 |
| 无障碍 | 大字号、触控区域、对比度和阅读顺序同时设计 | 真机与辅助技术验收 |

[Material颜色角色](https://m3.material.io/styles/color/the-color-system)可用于统一设计和代码。[Android主题指南](https://developer.android.com/design/ui/mobile/guides/styles/themes)建议响应系统主题偏好，并为动态主题提供回退。具体配色仍需检验对比度。

## 视觉验收

- Android实际触控区域至少48×48dp，图标本体可更小。Apple按钮指南的44×44pt属于另一平台尺度。依据：[Android无障碍](https://developer.android.com/guide/topics/ui/accessibility/apps)、[Apple按钮指南](https://developer.apple.com/design/human-interface-guidelines/buttons)。

- 在100%和200%系统字号、现有窄屏样例及vivo真机检查关键字段、单位和按钮。Android14起支持最高200%的非线性字体缩放，应实际验证。依据：[Android字体缩放](https://developer.android.com/about/versions/14/features#non-linear-font-scaling)。

- WebView核对viewport、页面缩放和文字适配，按最终设备呈现验收；CSS px、Android dp与iOS pt不机械互换。依据：[WebView屏幕适配](https://developer.android.com/develop/ui/views/layout/webapps/targeting)。

- 正常大小正文以至少4.5:1文字对比度为目标，适用大字至少3:1；字号类别按Android无障碍指南核对。状态同时有文字或其他线索。

- 键盘出现后当前输入与保存可达；状态栏、刘海和手势区不遮挡关键操作；返回顺序可预测。依据：[Android系统栏与insets](https://developer.android.com/develop/ui/views/layout/edge-to-edge)。

- TalkBack实操验证名称、值、顺序、错误、弹层焦点和返回焦点；低动态方案保留必要反馈。

- 空白、0、部分记录、草稿、保存失败、休息与单位不一致分别呈现。保留必要覆盖风险、权限、功能限制和署名，避免自我辩护、重复安慰、内部实现解释及无关流程预告。

| 外部备份便捷化 | v2.1.0至v2.4.0期间按使用需求单独安排 | 用户选择目录与范围；明确日期、轮换、权限失效和失败；本机快照不能替代设备外副本 |
| 性能和长期数据检查 | v1.6.7建基线，v2.2.0与v2.3.0交付后复测 | 记录启动、保存、查询、导出及内存；代表性长计划和流水；按实际瓶颈优化 |
| SQLite或Room | 查询关系、事务维护或整文件读写出现实测压力 | 独立迁移；临时目标校验后切换；保留旧数据；JSON/ZIP备份兼容；不长期双写 |
| 可延后后台维护 | 周期备份或维护需求明确时 | 评估WorkManager等方案，与学习计时及即时保存分别处理 |

[Android命令行构建](https://developer.android.com/build/building-cmdline)支持Gradle Wrapper与构建类型；[Room迁移指南](https://developer.android.com/training/data-storage/room/migrating-db-versions)强调迁移路径和数据验证。库版本按现有Java工程、最低系统和工具链兼容性选择。

采用Material和HIG不要求整套改用Compose、Flutter或React Native。更换语言或界面框架由具体模块收益决定。

# 交付和验收规则

## 业务兼容边界

手动保存与草稿分离；未填不等于0；休息保留真实学习值；参考不写入实际；历史单位、评估依据和课程快照可追溯；多计划隔离；活动计时归属明确；正式签名和旧更新路径继续可用。 新评估使用固定的原计划依据；事后改目标、改日程或移走任务不静默改善原计划结果。

## 每阶段交付

- 完成项、未完成项及对应页面或模块。

- 新增设计或规则决定及生效范围。

- 相关验证结果，区分模型、模拟器、真机和实际网络。

- 数据改变时提供迁移、备份往返与正式旧版覆盖升级结果。

- 可运行产物或原型，以及下一阶段可使用的组件和接口。

- 更新一份权威进度表，旧规划中已交付事项标为完成或归档。

## 发布安排

主线发布顺序为v1.6.7、v1.7.0、v2.0.0-beta.1、v2.0.0-beta.2、v2.0.0、v2.1.0、v2.2.0、v2.3.0、v2.4.0。Beta通过测试分发，不替换现有正式自动更新清单。用于覆盖安装的分发构建按实际发布顺序递增versionCode，正式v2.0.0高于两个Beta；插入修复版时顺延，不复用已发布编号。构建迁移、数据库迁移继续单独立项与验收，不能为凑版本号强行实施。

优先补真实设备和恢复场景证据，复用既有测试。样式调整检查关键界面；数据和规则改变执行对应回归，不以增加数量为测试目标。

## 首轮启动范围

先完成v1.6.7的基线核查和明确问题修复，再并行推进v1.7.0架构整理与面向v2.0.0的视觉设计。首轮产物为现状清单、问题及性能基线、设计体系、全页面状态覆盖表、三条关键原型，以及必要接口和共享规则样例。

随后按v2.0.0-beta.1和beta.2完成两批视觉实现，通过完整验收后发布v2.0.0；再推进v2.1.0自动评估与个人规则、v2.2.0每日任务、v2.3.0回顾队列和v2.4.0行动型复盘。v2.5.0模板与v2.6.0阶段目标在启动条件满足后实施。
