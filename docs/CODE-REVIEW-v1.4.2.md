# v1.4.2 代码审查

基线f4de055（v1.4.1交付），工作区原本干净。沿用Java/WebView架构、签名与更新通道。

**历史依据**

schema5新增按日期保存的assessmentBases，包含规则版本1、来源、留存时间、计划内标记、计时科目参考与新学目标。不存重复的实际值或预计算结论，实际记录修改后仍根据同一依据计算。

- 旧schema1—4读取为schema5视图，不重写旧文件，也不在读取时补造历史依据。未留存日期显示“当前参考（未留存）”。
- 正式保存新增记录时留存参考；既有记录在升级后首次保存时，留存操作前可取得的参考，标记“首次留存参考”。这不等于恢复旧版本中更早的原始目标。
- DataStore.save在持久化前读取当前已保存状态，为缺失依据的既有日期保留旧参考。修改每日参考、默认值、科目启用期或计划日期不会静默替换已有依据。首次留存仍受原有写入校验、恢复日志与版本冲突控制。
- 主动重评先克隆并展示原结果及当前目标结果；确认时校验真实活动计划与_revision。取消、失败或预览过期不提交；过期按钮可重新预览，写入失败可重试。重评只替换指定日期的依据，实际、周目标和计时会话不变。
- JS和Java均检查完整字段、已知规则、来源、有效UTC毫秒时间、布尔值、科目ID与类型、重复项、参考边界及词数。依据日期必须对应已保存记录；旧schema不能携带新字段。

**计算与筛选**

时长仍按照常、减量50%、仅回顾课程复习及休息规则计算；空值、0和部分记录分别处理。新学与复习分开，多词数科目未记齐时不判整日失败。该规则沿用v1.4.1的阈值边界和浮点误差容限。

达标率分母只包含完成、超额、未完成日期；分子为完成加超额。休息、未记录、待补全、未设目标与未选安排不进入分母。分母0时不显示百分比。统计忽略未来且未记录的日期，保留提前保存的真实记录。

历史评估筛选叠加原日期、科目、关键词、安排及记录状态。仅“未记录”评估筛选补入计划内没有保存记录的日期；默认历史列表不扩成空白日历。科目筛选不改变当天整体评估依据。依据保存后，归档或重排不会改变旧日期的评估科目范围。

**展示与导出**

- 今日评估保留简短结果，“评估依据”提供来源、时间、各科参考、已保存安排、实际和有效区间；编辑中的结果继续显示待保存。
- 历史提供时长/单词新学及结果两个标签明确的控件。周/月汇总可直接打开相应日期和评估筛选；每日结果、每周趋势用文本呈现，保留黑白布局。
- CSV原20列顺序保留，追加依据来源、留存时间、评估新学目标3列；当前目标与评估目标可不同。PDF列出有效区间和来源，沿用原字体、分页和来源许可。
- 生产持久化成功后重新读取已保存状态，使原生层补充的依据及时进入页面。连续保存不重新生成已有依据时间。
- 小组件当前参考与留存时长依据不同时，结果标记“按原区间完成/超额/未完成”，区分当前安排与历史依据；保留记录计数和原布局。

结果及未验证范围见[V1.4.2](V1.4.2.md)。
