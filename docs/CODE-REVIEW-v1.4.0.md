# v1.4.0 相关代码审查

2026年10月18日。范围是清单的数据、草稿、页面、备份和报表链路，以及直接关联的既有编辑逻辑。

| 问题 | 处理 | 验证 |
|---|---|---|
| 关闭的表单仍刷新草稿，旧值覆盖后续输入 | 关闭时移除弹层内容；flush跳过关闭的dialog | 编辑器保存后再从今日勾选、切复盘返回；单词及独立表单40项回归 |
| 科目和课程操作固定写schema2 | schema1/2/3可读；相关操作保留更高版本 | 归档/恢复、排序、词数、快捷值、课程安排后保留任务；Java/JS同步 |
| 数组覆盖会丢独立修改 | 稳定ID匹配，名称、科目、完成分别三方合并；冲突逐项选择 | 不同任务、不同字段、同字段、删除与修改、顺序冲突 |
| 调整日期使旧周不可达 | 保留日期键，历史取文字/随记/任务键的并集 | 开始日移动、范围缩短、编号变化及手动移周 |
| 勾选可能被当成学习量 | plan.weekTasks单独存储，数量统计仍按records/sessions | 0、空白、部分记录、词数、时长和历史统计不变 |
| 草稿单字段长度不足 | 仅week-tasks放宽到128KiB字符，其余仍8000字；保留条目和总字节上限 | 50项各500字原生回读，旧字段超限继续拒绝 |
| 新计划可能复制完成状态 | 界面创建空任务，原生拒绝已完成任务 | 原生检查与实际多计划切换 |

规则集中于weekly-goals.js，交互集中于weekly-ui.js；持久化与导入前由原生独立校验。每周50项、全计划10000项及4MB状态上限在写入前执行。已有恢复日志、覆盖确认和签名校验沿用。

任务时间是保存操作时间。移周先构造、校验候选计划，再提交；取消及超限不改原计划。CSV保留原列，PDF单独展示清单计数。任务改名时同时更新勾选、排序和删除控件的无障碍名称；无需重新创建输入框。执行结果及未验证范围见[V1.4.0](V1.4.0.md)。
