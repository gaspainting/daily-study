# 每日激励：需求评估与下一版功能说明

更新日期：2026年10月13日。状态：用户已批准的v1.1.0开发已完成；后续要求取消离线插画，尽可能联网取得正常图片，已落实。v1.0.0安装包不包含该功能，v1.1.0已加入。

本文保留开发前确认的要求与方案评估。当前实现、实际验证和限制以[V1.1.0开发与验证说明](每日学习-v1.1.0_开发与验证说明.md)及[插图来源与选择核查](插图来源与选择核查.md)为准；vivo X100s真机尚未连接。

## 一、已经确认的要求

| 项目 | 已确认的行为 |
|---|---|
| 启动展示 | 重新启动APP时展示插图和文字，每次随机，持续5秒，可点击跳过。 |
| 后台返回 | 切换其他APP、锁屏后返回，直接进入原页面，不重新播放启动展示。 |
| 每日抽签 | 每天抽取一次，抽到的日签当天固定，可以反复查看。 |
| 内容关系 | 启动图文每次随机，日签当天固定，两者不要求共用同一张卡。 |
| 图文形式 | 一幅插图配一段文字，可以独立搭配，也可以使用相互贴合的配套内容。 |
| 内容范围 | 不限制风格、色彩、类型、主题和情绪。激励、奋斗、爱情、心情、青春、emo、低落、天气、日出日落等均可。 |
| 文字 | 长短和语言不限，外文附中文释义。 |
| 更新与去重 | 插图和文字都尽量不重复，保留使用记录进行检查；不要求严格永不重复。 |
| 来源与费用 | 优先使用免费公开图文来源，接受AI生成内容。 |
| 留存与导出 | 收藏、历史回看、保存图片、分享都需要。 |

“每日激励”是模块名称，内容不应因此只剩热血或正向句子。用户允许各种情绪，也允许照片、艺术作品、插画等不同视觉类型。插图可以使用任意色彩；学习记录页面延续黑白纸质风格。

## 二、可行性与工作量判断

★ 可以加入当前安卓APP，整体属于中等规模功能扩展。页面、动画、每日一次、收藏等本地功能较直接；主要工作集中在图文来源的稳定性、中文释义准备、图片留存、分别去重，以及包含图片的备份恢复。

基础方案不需要先建设账号系统或云端学习数据库。联网用于准备素材，计划、实际学习时间、计时会话和复盘继续保存在手机。已有计时和休息规则与该模块分别处理，浏览日签不计入学习时间，也不需要等到允许学习的时段才能查看。

免费公开来源可以支撑第一版，但单个来源无法保证覆盖所有风格、任意外语、配套图文以及长期稳定的新内容。建议使用可替换的来源和本地素材池；“接受AI生成”先体现为允许收录AI内容，实时在线生成作为可选扩展，不承诺永久免费的生成或翻译服务。

## 三、建议的启动展示流程

1. 用户重新启动APP时，从已经准备好的本地图文池随机选择一张卡，显示5秒倒计时和清楚可见的“跳过”。
2. ★ 网络请求不延长这5秒。图片、文字以及所需中文释义应在展示前就绪；联网准备后续候选在后台完成。
3. 5秒从图文实际出现时计算，结束后进入APP；点击跳过立即进入。使用轻微淡入即可，尊重系统减少动画的设置。
4. 从后台返回、旋转导致页面重建、关闭文件选择器或系统权限界面时，不重新展示。启动展示不暂停、结束或重新开始学习计时。
5. 每次展示都记录卡片、图片、文字及展示时间。优先选未展示或较久未出现的内容，避免连续启动看到相同图文。

**不限文字长度与5秒展示的处理建议：** 开屏只显示适合当前屏幕的节选，明确标注“节选”。全文和外文中文释义仍完整保存，在模块的“开屏回看”中可查看；节选不替换原文，也不把字号缩小到难以阅读。该处理属于建议的交互细节。

★ 最新用户要求覆盖原先兜底建议：不采用内置离线插画或本地生成替代图片。优先联网获取真实照片与公开艺术作品，已联网取得的图片可以保留为本地缓存。首次尚无图片时显示获取状态并允许跳过，等待超时进入学习页面；获取失败不消耗日签资格。

## 四、建议的每日抽签流程

| 当天状态 | 页面行为 |
|---|---|
| 尚未抽取 | 显示“抽取今日日签”；点击后选择符合去重优先级且完整就绪的图文。 |
| 正在准备 | 显示简短进度，避免重复点击产生多个日签；可以离开页面继续使用APP。 |
| 已经抽取 | 显示固定的当天日签，操作改为查看、收藏、保存图片和分享。 |
| 获取失败且无可用缓存 | 显示失败原因和重试入口，保留当天抽取机会。 |
| 获取失败但有可用缓存 | 使用完整缓存正常抽签，成功后固定保存，不因稍后联网而换卡。 |

★ 抽取成功以完整内容保存到本地为准。图片未下载完成，或外文尚无中文释义，都不应先消耗抽取机会。快速重复点击、关闭APP再打开、断网、重启手机，均不能把已经抽到的当天日签换掉。

建议以手机本地日历日期为一天，不以抽取后24小时为周期。跨过零点后获得新日期的抽取资格，昨日卡保留在历史中；相同日期重新进入读取同一张卡。更改时区或系统日期时按当前日期查找历史，已有对应日期就复用该记录，不覆盖它。

长文详情允许滚动，显示原文、中文释义及已知出处。混合语言内容对外文部分提供中文解释；无法可靠准备释义的内容暂不进入可抽取池。启动素材与日签可共用来源池，但分别记录“开屏展示”和“日签抽取”，并优先避免当天两者重复。

## 五、素材准备与分别去重

建议按“获取候选 → 核对来源 → 下载图片 → 准备释义 → 检查历史 → 标记可用”的顺序处理。只有准备完整的卡片进入可用池，提前储备少量素材以应对弱网或连续几天无网。

| 去重对象 | 建议依据 | 能够检查的范围 |
|---|---|---|
| 插图 | 来源及图片ID、下载文件SHA256；必要时增加视觉相似度摘要 | ID相同或字节相同可以判为重复；裁剪、压缩或换尺寸后的近似图需要相似度判断。 |
| 文字 | 来源及文字ID、规范化原文摘要 | 同一句文字即使换图或换出处字段，仍计为文字重复；仅改变空白、大小写等不视作全新内容。 |
| 整张卡 | 图片标识与文字摘要的组合 | 保留组合历史，但换一个组合不代表图和文字分别都是新的。 |
| 外文释义 | 关联原文及译文版本 | 更新中文解释不会把同一段外文当成新文字，也不会改掉已经抽到的历史卡。 |

★ 用户确认的是“图和文字都尽量不重复”。建议优先选择两者均未使用的候选；不足时先扩大候选或更换来源，再考虑较久未出现、使用次数较少的内容。内容不足时允许温和复用并记录重复状态，不承诺无限素材，也不把复用内容标记为首次出现。

日签历史和开屏历史均参与检查。每日固定卡、收藏卡、全文与来源长期留存；待展示的临时素材可清理。来源ID、摘要和展示日期属于轻量记录，即使用户主动清理某些图片，也应尽量保留去重记录。

仅凭随机接口、日期seed或不同URL不能证明内容不同。去重应以实际取到的图与文字为依据。

## 六、候选来源评估

以下为依据2026年10月13日官方说明完成的前期候选评估。v1.1.0已接入前三项来源，未接入Pollinations；尚未在vivo X100s的网络环境实测。实际图片规则已再次核查，详见[插图来源与选择核查](插图来源与选择核查.md)。

| 来源 | 可承担的内容 | 对本APP的意义与实际限制 |
|---|---|---|
| [一言语句接口](https://developer.hitokoto.cn/sentence/) | 中文短句、出处、作者、类别、唯一标识 | 可以补充多类语句；按使用协议保留来源，使用本地缓存并节制请求。其随机结果不保证不重复，应记录UUID及原文摘要。 |
| [Lorem Picsum](https://picsum.photos/) | 照片、图片ID、作者和来源信息 | 可按ID固定获取图片，也能查询元数据。适合补充照片；按日期seed固定结果不代表不同日期一定是不同图片。 |
| [Met开放藏品API](https://metmuseum.github.io/) | 开放艺术作品、图片和艺术家信息 | 官方无需API Key，可补充艺术作品；选择有图且isPublicDomain=true的素材。不能据此承诺任意主题都有现成匹配图，实现时应使用官方当时支持的API版本。 |
| [Pollinations官方仓库/API说明](https://github.com/pollinations/pollinations) | 按主题生成文字、图像 | 官方接口涉及API Key及Pollen额度计费，不能直接视作永久免费的实时来源。预先生成后收录、或以后选择实时生成均可另行评估。 |

外文释义建议优先采用已有中外文配套内容，或预先完成并核对释义后收录。若引入在线翻译，还需单独验证免费额度、语言覆盖、连通性及翻译质量；当前不指定尚未核实的免费翻译接口。

来源信息与使用条件随素材保存。保存和分享卡片时保留必要署名；“公开可访问”本身不等于允许任意下载或再分发，取图前需确认具体素材可用于这些功能。

## 七、收藏、历史、保存与分享

- **历史：** 按日期查看日签，另提供开屏回看，避免当天多次启动混入每天一张的日签列表。启动被跳过也可保留已经展示的卡，方便以后读全文。
- **收藏：** 日签和开屏内容均建议可收藏；收藏状态不受当天结束、再次启动或临时素材清理影响。取消收藏不会删除对应历史。
- **保存图片：** 导出包含插图、文字、日期及必要来源的图文卡。外文附中文释义，避免只保存图片而丢掉文字。
- **长文导出：** 建议在手机可读字号下生成长图；过长内容分成带页码的多张图片，保留全文与释义，不静默截断。具体分图阈值在实现时按设备图片尺寸和内存校验。
- **分享：** 用户点击后调用安卓系统分享面板，选择目标；可以分享完整图文图片及配套文字。取消分享不会改变日签、收藏或当天资格。

上述导出使用本地已保存内容，不重新请求一张随机图片。历史回看也读取保存的图片文件，避免远程链接更新或失效后变成另一张图。

## 八、本地存储、备份与升级建议

每张图文卡建议记录：本地卡片ID、适用日期、抽取或展示时间、完整原文、语言、中文释义及译者/方式、图片文件与摘要、主题、作者、图文来源、素材使用条件、是否AI生成、收藏状态及重复情况。开屏展示次数和每日抽取记录分别保存。

★ 历史图文必须保存实际图片，不能只保存网址。收藏和已抽到的日签不作为普通临时缓存自动淘汰；提供存储占用查看与主动清理方式，清理前说明受影响的历史图片。

建议增加包含学习数据、日签、开屏记录、收藏、去重记录和媒体文件的ZIP完整备份，同时继续允许导入原有v1.0.0 JSON学习备份。导入旧版备份时保留既有学习字段，并明确它不包含图文；新备份则检查格式、图片清单和数据一致性后整体恢复。

新版本需要增加网络能力、媒体保存与分享支持，并迁移本地数据格式。沿用现有安装签名升级，避免要求用户卸载旧版；迁移失败时保留原数据并允许恢复。学习记录不作为素材或翻译请求发送给来源服务。

## 九、建议的实现与验收顺序

1. **本地完整流程：** 使用示例素材完成5秒随机开屏、跳过、全文回看、每日一次、收藏和历史，先验证与计时、后台返回的配合。
2. **联网素材：** 接入经过试取的免费来源，完成缓存、中文释义、分别去重、失败重试和重复状态记录。
3. **保存与分享：** 完成长文图片排版、来源标注、系统分享及完整媒体备份。
4. **设备验证：** 在Android 16检查启动、进出后台、权限界面、相册保存和分享；再在vivo X100s检查实际联网与显示效果。

第一版验收应包括：

- 重新启动展示5秒且可随时跳过；后台返回、文件选择器返回不重新播放，正在运行的计时保持正确。
- 连续启动随机选择素材，分别记录图片和文字历史；不同组合不能绕过单独去重。
- 同一天快速重复点击、关闭后重开、断网、重启手机，均只保留一张已抽到的日签；跨日期可以抽取新卡。
- 请求失败、图片缺失或释义未完成不消耗机会；缓存齐全时无网可抽，缓存耗尽也能继续使用学习功能。
- 外文附中文释义；长文可完整阅读，保存/分享不会丢失尾部文字。
- 收藏和历史离线可用；导出与恢复后图文、来源、收藏、去重和学习数据一致。
- 覆盖升级保留原有计划、实际记录、计时会话、复盘和提醒设置，旧版JSON备份仍有导入路径。

当前关键需求已在v1.1.0实现。以上前期建议以用户后续要求为准，最终来源选择与图片核查规则见《插图来源与选择核查》，实现及验证见每日学习-v1.1.0_开发与验证说明.md。
