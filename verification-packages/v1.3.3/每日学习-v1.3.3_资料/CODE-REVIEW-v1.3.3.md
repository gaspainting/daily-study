**算法调整**

| 算法 | 原流程 | 本轮流程 |
|---|---|---|
| 历史筛选 | 所有日期先排序，匹配记录摘要计算两次 | 先做日期/科目/安排/关键词筛选，每条摘要一次，只排序匹配结果 |
| 计时明细 | 全部会话先克隆，比较器重复解析结束时间 | 保留原去重优先级，先筛选，结束时间解析一次，克隆最终结果 |
| 报表科目合计 | 每个科目再次扫描全部行，O(行数×科目数) | 单次扫描构建各科合计，O(行数+科目数) |
| 日签检索 | 同一请求读取并验证状态两次 | 请求内复用一次已校验快照，不做跨请求持久缓存 |
| 小组件刷新 | 每个组件读取、迁移与验证相同学习文件 | 一次读取生成内容，复用于本批组件 |
| 草稿保存 | 相同值也重写文件和修改时间 | 基线与编辑值相同则不重复写入；有变化仍立即持久化 |
| 前端读状态 | 迁移校验后再次执行相同全量校验 | 保留迁移内的校验，移除额外重复步骤 |

5000条记录、10000次计时的2.63MB合成数据与旧版查询逐项对照，结果完全相同。本机9次采样中位值：完整历史约84.0→63.7ms，完整计时约43.1→39.7ms，日期/科目筛选计时约38.6→32.8ms。窄日期关键词历史约32.0→33.2ms，该项没有测得加速。结果见 [微基准](validation-v1.3.3/algorithm-benchmark.json)，为本机Node执行结果。

**延续的保护与边界**

正式记录手动保存，草稿独立。词数和分钟分开，复习不抵扣新学，休息状态不将数值归零。版本来自构建及安装元数据，更新包仍验证同签名与真实版本。备份先校验并显示实际范围，取消不覆盖；历史字段、参考分钟和会话保留。启动与日签图片继续使用联网所得图片及其实际来源。

目前不新增周任务清单、AI、账号或云同步。真机、Android8–15及旧WebView兼容未验证；原界面使用现代JavaScript，最低SDK声明本身不代表所有旧WebView均经过验证。真机读屏播报和厂商省电调度仍需设备验证。

最终构建、实际运行结果、页面截图和发行摘要见 [v1.3.3交付报告](V1.3.3.md)。
